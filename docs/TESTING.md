# 별도 PC에서 확인하는 방법

이 문서는 사전 릴리스용입니다. Windows 7 SP1 x64에서 먼저 확인하고 Windows 10·11 x64의 격리 환경에서 같은 시험을 반복하세요. 시험은 **해당 PC의 로컬 화면**에서 진행합니다. 실제 외부 인터넷 대신 서로 라우팅되는 두 시험망을 사용해도 됩니다.

1. `winver`로 OS 빌드(Windows 7 SP1은 7601)를 확인합니다. 맞는 설치 파일을 설치하고 시작 메뉴에서 실행해 관리자 권한을 승인합니다.
2. 인트라넷 어댑터와 내부 주소를 확인합니다. 같은 서브넷 밖의 업무 서버와 내부 DNS도 입력하고 저장합니다. 외부 시험 서버와 외부 시험 DNS는 허용 목록에 들어가면 안 됩니다.
3. 허용 상태에서 내부 업무 사이트와 내부 DNS가 정상인지 확인합니다. 외부는 **실제로 응답하는 시험 서버**의 숫자 IP와 TCP 포트를 사용합니다. 별도의 외부 DNS 서버는 UDP 53으로 응답해야 합니다. 아래 명령의 꺾쇠 부분은 시험망 값으로 바꿉니다.

   ```powershell
   cd "$env:ProgramFiles\Toggle External Connection"
   $lab = @{InternalName='<내부 업무 호스트명>'; InternalPort=443; ExternalIP='<외부 TCP 서버 IP>'; ExternalPort=443; ExternalDnsIP='<외부 DNS IP>'; DnsTestName='<조회할 도메인>'}
   .\check-lab.ps1 -Phase Before @lab
   ```

   PowerShell 스크립트가 조직 정책으로 제한된 경우 위 명령 대신 브라우저로 내부 사이트와 외부 IP 접속을 확인하고 `nslookup 도메인 외부DNS주소`로 직접 비교할 수 있습니다. 스크립트는 접속을 시도하고 콘솔에 결과만 출력합니다.

4. 가능하면 차단 **전**에 외부 시험 서버에서 큰 파일 전송 또는 지속적인 UDP 전송을 시작합니다. 트레이 메뉴의 **60초 시험 차단**을 누릅니다. 차단 중 같은 PowerShell 창에서 다음을 실행합니다.

   ```powershell
   .\check-lab.ps1 -Phase Blocked @lab
   ```

   내부 DNS·업무 사이트가 계속 작동하고, 외부 TCP·UDP와 진행 중이던 외부 전송은 멈춰야 합니다. `nslookup`은 출력에서 DNS 응답 유무를 직접 확인합니다. 내부 사이트가 캐시된 화면을 보여 줄 수 있으므로 내부 TCP 응답도 함께 확인합니다.

5. **차단 기록 보기**에서 `powershell.exe`의 시험 IP·TCP 포트와 `nslookup.exe`의 외부 DNS IP·UDP 53을 **각각** 찾아 전체 실행 경로를 확인합니다. 같은 목적지로 수차례 반복해 관측 횟수를 봅니다. 허용된 내부 목적지와 차단 전 접속은 이 목록에 없어야 합니다.
6. 60초 뒤 허용 상태로 돌아오면 `.\check-lab.ps1 -Phase Restored @lab`를 실행합니다. 새 외부 접속이 성공하고 추가 차단 기록이 생기지 않아야 합니다. 중단된 TCP 전송은 새로 연결해야 할 수 있습니다.
7. 가능하면 두 주소 계열에서 실제 응답하는 서버로 IPv4·IPv6를 각각 검사합니다. 차단 중 Wi-Fi 등 두 번째 경로를 연결해 외부 우회가 없는지도 확인합니다. DHCP 임대 갱신과 내부 이름 조회를 시험망에서 확인하세요.
8. 별도 시험으로 차단 중 앱을 종료하거나 작업 관리자에서 프로세스를 종료합니다. 새 외부 연결이 복구되어야 합니다. 다시 차단한 상태에서 재부팅해도 인터넷은 허용 상태여야 합니다. 앱을 열어 과거 7일 이내 기록을 조회하고, 마지막으로 제거 후 외부 연결을 확인합니다.

시험 결과에는 OS 빌드와 단계별 성공·실패만 있으면 됩니다. 사내 IP·도메인·사용자 경로나 로그 원문은 공개 이슈에 붙이지 마세요. OS별 실제 차단·복구 결과를 확인하기 전에는 정식판으로 승격하지 않습니다.
