# 별도 PC에서 확인하는 방법

Windows 7 SP1 x64에서 먼저 확인하고 Windows 10·11 x64의 격리 환경에서 같은 시험을 반복하세요. 시험은 **해당 PC의 로컬 화면**에서 진행합니다. 실제 외부 인터넷 대신 서로 라우팅되는 두 시험망을 사용해도 됩니다.

1. `winver`로 OS 빌드(Windows 7 SP1은 7601)를 확인합니다. 맞는 설치 파일을 설치하고 시작 메뉴에서 실행해 관리자 권한을 승인합니다.
2. 인트라넷 어댑터와 내부 주소를 확인합니다. 같은 서브넷 밖의 업무 서버와 내부 DNS도 입력하고 저장합니다. 외부 시험 서버와 외부 시험 DNS는 허용 목록에 들어가면 안 됩니다.
3. 허용 상태에서 내부 업무 사이트와 내부 DNS가 정상인지 확인합니다. 외부는 **실제로 응답하는 시험 서버**의 숫자 IP와 TCP 포트를 사용합니다. 별도의 외부 DNS 서버는 UDP 53으로 응답해야 합니다. 아래 명령의 꺾쇠 부분은 시험망 값으로 바꿉니다.

   ```powershell
   # 설치 화면에서 선택한 실제 경로로 이동
   cd "D:\Toggle External Connection"
   $lab = @{InternalName='<내부 업무 호스트명>'; InternalPort=443; ExternalIP='<외부 TCP 서버 IP>'; ExternalPort=443; ExternalDnsIP='<외부 DNS IP>'; DnsTestName='<조회할 도메인>'}
   .\check-lab.ps1 -Phase Before @lab
   ```

   PowerShell 스크립트가 조직 정책으로 제한된 경우 위 명령 대신 브라우저로 내부 사이트와 외부 IP 접속을 확인하고 `nslookup 도메인 외부DNS주소`로 직접 비교할 수 있습니다. 스크립트는 접속을 시도하고 콘솔에 결과만 출력합니다.

4. 가능하면 차단 **전**에 외부 시험 서버에서 큰 파일 전송 또는 지속적인 UDP 전송을 시작합니다. 트레이 아이콘을 한 번 눌러 외부 연결을 차단합니다. 차단 중 같은 PowerShell 창에서 다음을 실행합니다.

   ```powershell
   .\check-lab.ps1 -Phase Blocked @lab
   ```

   내부 DNS·업무 사이트가 계속 작동하고, 외부 TCP·UDP와 진행 중이던 외부 전송은 멈춰야 합니다. `nslookup`은 출력에서 DNS 응답 유무를 직접 확인합니다. 내부 사이트가 캐시된 화면을 보여 줄 수 있으므로 내부 TCP 응답도 함께 확인합니다.

5. **차단 기록 보기**에서 `powershell.exe`의 시험 IP·TCP 포트와 `nslookup.exe`의 외부 DNS IP·UDP 53을 **각각** 찾아 전체 실행 경로를 확인합니다. 같은 목적지로 수차례 반복해 관측 횟수를 봅니다. 허용된 내부 목적지와 차단 전 접속은 이 목록에 없어야 합니다.
6. 트레이 아이콘을 다시 눌러 차단을 해제한 뒤 `.\check-lab.ps1 -Phase Restored @lab`를 실행합니다. 새 외부 접속이 성공하고 추가 차단 기록이 생기지 않아야 합니다. 중단된 TCP 전송은 새로 연결해야 할 수 있습니다.
7. 가능하면 두 주소 계열에서 실제 응답하는 서버로 IPv4·IPv6를 각각 검사합니다. 차단 중 Wi-Fi 등 두 번째 경로를 연결해 외부 우회가 없는지도 확인합니다. DHCP 임대 갱신과 내부 이름 조회를 시험망에서 확인하세요.
8. 별도 시험으로 차단 중 앱을 종료하거나 작업 관리자에서 프로세스를 종료합니다. 새 외부 연결이 복구되어야 합니다. 다시 차단한 상태에서 재부팅해도 인터넷은 허용 상태여야 합니다. 앱을 열어 과거 7일 이내 기록을 조회하고, 마지막으로 제거 후 외부 연결을 확인합니다.

시험 결과에는 OS 빌드와 단계별 성공·실패만 있으면 됩니다. 사내 IP·도메인·사용자 경로나 로그 원문은 공개 이슈에 붙이지 마세요.

### 설치 경로·업데이트 확인

별도 PC에서 두 OS용 설치 파일을 각각 확인할 것. 설치 화면에 기본 `Program Files\Toggle External Connection` 경로와 폴더 선택 버튼이 표시되는지 확인할 것. 다른 로컬 NTFS 드라이브의 새 전용 폴더를 선택하고 실제 실행 파일·시작 메뉴·설정·기록이 선택한 경로를 사용하는지 확인할 것. 일반 사용자가 쓸 수 있는 상위 폴더와 정션·심볼릭 링크 경로는 거부되어야 함.

v0.1.0-rc.1 설치 후 설정·기록을 준비하고 앱을 종료할 것. 현재 버전의 설치 화면에서 다른 드라이브·폴더를 선택할 것. 설정·기록이 그대로 유지되고 이전 실행 파일·제거 프로그램은 정리되어야 함. 같은 폴더 업데이트도 반복할 것. 디스크 공간 부족·쓰기 실패에서는 원본 또는 새 위치의 검증된 `Data` 복사본이 남는지 확인할 것. 복구가 필요하면 두 `Data` 폴더를 보존하고 관리자 권한으로 새 위치에 다시 설치할 것. 제거 후에는 선택한 위치의 설정·기록이 삭제되는지 확인할 것.

GitHub Actions의 설치 시험은 폐기 가능한 실행기에서 기본 설치·같은 폴더 업데이트·공백이 포함된 다른 경로로 이동·설정 및 기록 바이트 보존·쓰기 가능한 상위 폴더 거부·제거를 확인함. 실제 Windows 7과 별도 드라이브의 수동 검증을 대신하지 않음.

### 09 / 추가 시험 — 범위 입력과 개발 앱 예외

| 항목 | 확인 방법 |
|:---:|:---|
| IPv4 패턴 | 실제 시험망에 맞는 `172.16.1.*` 형식으로 등록. 범위 안·밖의 응답 가능한 호스트를 각각 확인할 것. |
| Codex·Claude·Antigravity | 앱을 먼저 실행. 사용할 앱 하나만 체크하고 저장한 뒤 트레이 아이콘으로 차단. 선택한 앱에서 새 요청이 성공하는지, 미선택 앱은 차단되는지 확인할 것. |
| Git · gh | 체크 후 `git ls-remote https://github.com/git/git.git HEAD`, 인증된 `gh api rate_limit` 실행. 해제·저장 후 같은 시험을 반복할 것. |
| GitHub 웹 | MiniBrowser 0.2.4의 일반 창을 열어 둔 상태에서 체크 후 **MiniBrowser에서 GitHub 열기** 선택. 별도 MiniBrowser 창에서 저장소가 열리고, 같은 창에서 관계없는 외부 HTTPS 도메인은 거부되는지 확인할 것. 전용 창을 닫은 뒤 일반 창이 남는지도 확인할 것. Git · gh와 GitHub 웹은 서로 독립적으로 설정. |
| Google 로그인 | Google 로그인 옵션을 끄고 저장한 뒤 전용 창에서 Google 계정 주소가 거부되는지 확인할 것. 옵션을 켜고 저장한 뒤 GitHub의 **Continue with Google**에서 계정 화면이 열리는지 확인할 것. Google 검색과 Gmail은 두 경우 모두 차단되어야 함. 실제 계정 인증과 GitHub 복귀는 사용자 계정으로 확인할 것. |
| 해제·복구 | 트레이 아이콘을 다시 누른 뒤 외부 연결 복구, 예외 앱 연결이 차단 기록에 들어가지 않는지 확인할 것. |
| CSV 저장 | 기록 목록을 특정 프로그램으로 검색한 뒤 **CSV 저장** 선택. 한글 경로, 목적지 IP·포트, 횟수와 행 수가 화면과 일치하는지 확인할 것. 검색을 지우고 다시 저장하면 전체 목록을 내보내야 함. |
